# 메모장 작성·편집 개선안

작성일: 2026-10-15, 한국 시간  
상태: 검토안 — 구현 전  
범위: 네이버 메모 분석보고서와 현재 프로젝트 소스 비교. 앱 코드·DB 변경 없음.

## 결론

현재 Flutter Quill 편집기와 기존 데이터 구조를 유지하면서 **작성에 집중할 수 있는 화면, 변경사항 보호, 임시 초안 복구**를 먼저 보완하는 방향을 제안한다. 체크리스트·불릿·형광펜은 이미 있으므로 다시 만들 필요가 없다. 금액 목표와 반복 알림도 유지한다.

네이버의 HTML 편집기나 JavaScript 브리지를 도입할 필요는 없다. 참고할 것은 편집기 구현 기술 자체보다 **작성 상태, 임시 저장, 최종 저장, 동기화를 구분하는 설계**다.

## 3. 1차 개선: 작성 흐름과 변경사항 보호

### A. 작성에 집중할 수 있는 화면

현재 모바일 작성 화면에서는 본문 아래의 일정·알림 설정과 저장 버튼이 같은 스크롤 영역에 있다. PC는 저장 버튼이 대화상자 액션 영역에 있다. 두 화면의 배치 문제를 각각 해결한다.

- 모바일: 제목·본문을 중심에 두고 저장/닫기 동작을 찾기 쉽게 고정한다. 긴 본문에 적합한 별도 작성 화면을 검토한다.
- PC: 기존 desktop shell과 대화상자를 유지하면서 본문 영역과 부가 설정을 구분한다.
- 일정·반복·알림·소리·캘린더 표시 같은 설정은 ‘추가 설정’으로 접을 수 있게 한다. 설정 여부는 요약으로 보여준다.
- 금액 목표는 유형을 선택했을 때 현재처럼 입력할 수 있게 하되, 일반 메모 작성 영역을 방해하지 않도록 한다.
- 기존 알림의 권한 처리·완료 처리·반복 설정은 변경하지 않는다.

예상 흐름:

```text
새 메모
  → 제목·본문 입력
  → 필요한 경우 체크리스트·불릿·형광펜 사용
  → 금액 목표 또는 추가 설정 선택
  → 저장
```

제목을 선택사항으로 바꾸거나 첫 줄에서 제목을 자동 생성하는 기능은 별도 결정이 필요하다. 1차에서는 제목 필수·최대 120자 정책을 유지한다.

### B. 변경사항이 있을 때만 이탈 확인

- 새로 작성하거나 편집한 뒤 닫기·취소·뒤로가기·바깥 영역 클릭·모바일 시트 닫기로 나갈 때 변경 여부를 확인한다.
- 변경이 있으면 ‘계속 작성 / 변경사항 버리기 / 저장 후 닫기’를 제공한다.
- 변경이 없거나 편집 후 원래 값으로 되돌렸으면 확인창을 반복해서 띄우지 않는다.
- 비교 대상은 본문 글자뿐 아니라 서식, 제목, 금액 목표, 고정 여부, 일정·알림 설정도 포함한다.
- 저장 검증이나 DB 저장에 실패하면 편집 내용과 화면을 유지하고, 실제 실패 원인을 저장 동작 가까이에 표시한다.
- 저장 중에는 중복 저장과 편집 화면 종료를 제어한다.

여기서 ‘변경사항 버리기’는 사용자가 명시적으로 선택했을 때만 편집 내용을 폐기한다는 뜻이다.

### C. 도구 모음 개선

- 자주 쓰는 체크리스트·불릿·형광펜을 쉽게 찾을 수 있게 한다.
- 실행 취소·다시 실행 버튼을 추가하고 실행할 이력이 없을 때 비활성화한다.
- 글자 크기·굵게·밑줄·취소선·글자색 등 현재 기능은 유지한다. 좁은 모바일에서는 일부를 더보기로 정리한다.
- 현재 선택된 서식과 도구 이름을 알아볼 수 있게 하고, 키보드·스크린리더 접근성을 확인한다.
- 한글 조합 입력, 불릿 자동 변환, Enter로 항목 추가/종료가 실행 취소와 함께 정상 동작하도록 검증한다.

## 4. 2차 개선: 복구 가능한 임시 초안

### 임시 저장을 최종 저장과 분리하는 이유

현재 작업 폴더의 `NotesDao.saveNote()`는 메모와 체크리스트 저장 후 `ReminderStore.captureCurrent()` 및 반복 일정 계산으로 연결된다. 따라서 타이핑마다 기존 저장 함수를 호출하는 방식은 작성 중인 값이 최종 메모·완료 상태·알림에 반영될 위험이 있다.

임시 초안은 별도 저장소에 보관하고, 저장 버튼을 누를 때만 최종 메모로 반영하는 방향을 제안한다. 임시 초안을 저장했다는 이유로 알림 예약이나 본문 보기의 체크리스트 상태를 바꾸지 않는다.

### 제안하는 초안 정책

- 임시 초안은 메모 본문뿐 아니라 제목·서식·금액 목표·일정·알림 설정을 함께 보관한다.
- 저장소 후보는 별도 `note_drafts` 테이블이다. 신규 메모는 독립 초안 ID, 기존 메모는 원본 메모 ID와 원본 수정 시각을 함께 보관한다. 실제 스키마·migration은 구현 단계에서 확정한다.
- 입력이 멈춘 뒤 약 1초 후 초안을 저장하는 방식을 초기안으로 삼는다. 이는 네이버에서 확인된 수치가 아니라 제안값이다.
- 모든 편집 값의 변경을 감지하고, 앞선 저장 요청이 늦게 완료돼 최신 초안을 덮어쓰지 않도록 저장 순서를 관리한다.
- 정상적인 화면 이탈·앱 백그라운드 전환에서도 가능한 범위에서 저장한다. 강제 종료 순간의 마지막 입력까지 무조건 복구된다고 표시하지 않는다.
- 다시 열 때 ‘임시 작성 내용이 있습니다’와 함께 복구/버리기를 제공한다.
- 최종 저장 성공 후 해당 초안을 지운다. 저장 실패 시에는 초안을 남긴다.
- 새 메모의 초안 저장에는 제목 필수 검증을 적용하지 않는다. 제목이 없는 중간 입력도 복구할 수 있어야 한다.
- 기존 메모가 다른 화면의 체크 동작 등으로 변경됐다면 원본 수정 시각을 비교하고, 오래된 초안으로 자동 덮어쓰지 않는다.
- 초안은 기본적으로 로컬 복구용으로 취급한다. 전체 백업·복원·데이터 초기화 때 포함 또는 삭제할 정책을 함께 정한다.

### 상태 표시

| 상황 | 제안 문구 | 의미 |
|---|---|---|
| 아직 초안으로 기록되지 않은 변경 | 작성 중 | 현재 편집기 안의 내용 |
| 초안 저장 성공 | 이 기기에 임시 저장됨 | 최종 메모 저장이나 클라우드 동기화 완료를 뜻하지 않음 |
| 최종 메모 저장 성공 | 저장됨 | DB 확정 성공 |
| 저장 실패 | 저장하지 못했습니다 · 다시 시도 | 편집 내용 유지, 재시도 가능 |

초안 기능을 실제로 구현하기 전에는 ‘임시 저장됨’ 표시를 추가하지 않는다.

## 6. 구현 시 보존할 조건과 검증 기준

기존 일반 메모와 Delta JSON, 일반 텍스트 대체 표시, 금액 목표, 체크리스트·불릿, 본문 기본 크기 18을 유지한다. desktop/mobile 화면 분리 및 기존 shell의 플랫폼·폭 정책을 따른다.

| 검증 영역 | 확인할 결과 |
|---|---|
| 기존 데이터 | 기존 일반/목표/서식 메모 열기·수정·재저장, 이전 백업 복원 가능 |
| 편집 상태 | 본문·서식·금액·설정 변경을 감지하고 원상 복구 시 변경 없음으로 판정 |
| 이탈 경로 | 뒤로가기, 닫기, 취소, 바깥 클릭, 시트 제스처에서 내용 유실 방지 |
