# 구현 결과

- PC·모바일 자산 목록/상세: 사용자 후속 답변에 따라 신용카드는 오늘까지 쓴 금액/이번 달 전체 지출액(예정 포함), 그 외 자산은 현재/예상 잔액을 표시한다. 총액에도 예상 순자산을 추가했다.
- 카드 편집: 매월 결제일, 청구 마감일, 연결 출금 은행계좌. 다음 결제일의 예상 출금액과 이후 청구액을 분리한다. 미설정 값은 0원이 아니라 설정 필요/미연결로 표시한다.
- 오늘까지의 상환·환급은 오래된 이용액부터 반영하며, 미래 상환 거래는 결제 전 청구액을 없애지 않는다. 다음 청구에는 등록된 미래 지출도 포함된다. 실제 카드사 연동이나 자동 출금 생성은 없다.
- 신용카드 편집은 오늘까지 사용액을 불러와 입력값과의 차이를 오늘 사용액 조정으로 기록한다. 상환 이체 및 초기 부채는 이번 달 사용액에서 제외한다. 사용액 조정은 해당 날짜 청구분에 반영하여 지난달 청구액을 건드리지 않는다. 그 외 자산은 현재 잔액 기준으로 수정한다. 미래 거래는 변경하지 않는다.
- schema 27에 선택적 카드 설정 3개 추가. 출금계좌 UUID를 백업/동기화하고 이전 앱의 동기화에 필드가 없으면 기존 설정을 보존한다. 연결 은행계좌 삭제/종류 변경 보호, 보관 계좌 이름 표시, 전체 초기화 시 설정 제거를 포함한다.
- 모바일 수정 후 관련 거래·통계 갱신과 기존 자산 색 보존도 확인했다.

## 검증

- 정적 분석 lib/test: 문제 없음.
- 최종 전체 테스트 **648/648 통과** (`correction-full-tests.log`), 정적 분석 문제 없음 (`correction-analyze.log`). 추가된 22개 테스트는 청구/마감 경계, 휴일·짧은 달, 환급·상환, 현재/예상 잔액, 신용카드 기간별 사용액·사용액 수정, 신규 카드 월별 사용액, v26 마이그레이션, 구 백업/구 동기화 호환, PC/모바일 설정 및 화면을 검증한다.
- 늘어난 모바일 목록에 맞춰 보관 자산 복원 테스트는 스크롤 후 버튼을 누르게 변경했다. 실제 복원 결과 검증은 유지한다.
- PC 1300×980, 모바일 390×844 화면 캡처 확인 (`desktop.png`, `mobile.png`). 모바일 320px 표시와 PC 좁은 창/플랫폼 분리 회귀 테스트 포함.
- 별도 배포 요청이 아니므로 커밋·푸시·태그·Release·Play 배포 없음. 앱 버전은 직전 배포 버전을 유지한다.

## 후속

사용자가 '이후 추가'로 지정한 할부 회차·잔여액은 후속 구현 대상으로 남겼다. 추가 답변 '신용카드에 한해서 2번'을 반영하여 카드만 사용액/전체 지출액으로 분리했다.
