# 카드 할부 구현 결과

Status: ready-for-human

2026-11-19 구현 및 검증 완료. 기능 보완 요청에 따라 작업했으며, 버전은 기존 1.0.0-rc.18+67 유지. 이번 변경은 아직 게시하지 않았다.

이후 사용자 배포 요청을 받아 rc.19+68 릴리스를 준비한다. 배포 절차와 검증은 ../release-rc19/PRD.md에 기록한다.

## 구현

- 신용카드 지출에서만 일시불·2~60개월 선택. PC 입력/편집/복사, 모바일 입력/편집/복사, 양쪽 프리셋 화면에 적용. 결제수단 또는 거래 유형 변경 시 할부 선택 초기화.
- 원거래에 총액과 개월 수를 저장하여 지출·예산·전체 부채의 중복 집계를 방지. 결제일·마감일 기준으로 청구 원금만 월별 분배. 나머지 원은 첫 회차에 합산.
- 카드별 이번 청구 회차, 이후 회차별 날짜·금액·잔여 원금. 상세 목록은 상환·환급 전 예정 원금으로 명시하며 카드 전체 예상 청구액에는 오늘까지 실제 기록한 상환·환급 반영. 수수료는 별도 지출로 입력.
- 월말과 공휴일 이동을 반영하며 결제 주기는 명목 결제 월로 식별. 날짜 경과만으로 상환 완료 처리하지 않음.
- 거래/자산 상세 목록 할부 표시, 프리셋 재사용, CSV 입출력과 중복 판정에 개월 수 반영.
- DB 28→29: transactions/transaction_presets에 nullable installment_months 추가. 기존 거래/구 백업은 일시불. 백업·동기화 보존; 구 클라이언트의 필드 생략은 기존 값 유지, 명시적 NULL은 할부 해제.
- DAO에서 신용카드 지출·개월 범위·회차당 최소 1원 확인. 할부 거래가 있는 카드의 다른 자산 종류 전환 차단.

## 검증

- 전체 테스트 689/689 통과(full-tests.log). 이후 PC·모바일 프리셋으로 새 할부 거래 저장하는 검사 2개를 추가하여 최종 관련 데이터/UI 18/18 통과(final-checks.log). 신규 기능 검사 총 27개(계산 9, 데이터 9, UI 9).
- 최종 lib/test 정적 분석 진단 없음(analyze.log), git diff --check 통과.
- 원금 보존, 60개월·월말·휴일·연도 전환, 동일 마감일 주기 구별, 미상환 이월, 미래 상환 제외, 환급, 수정/삭제/복사, 신용카드 전용 활성화, 프리셋 저장, 구 DB 마이그레이션, 백업·동기화·CSV 확인.
- 실제 PC(1100×900)/모바일(390×844) 경로에서 입력/회차 화면 캡처 확인. 좁은 320px 카드 요약 펼침도 오버플로 없이 통과.
- 캡처: desktop-entry.png, desktop-schedule.png, mobile-entry.png, mobile-schedule.png. 캡처 전용 실행 파일은 build/card-installments/capture_test.dart(버전 관리 제외). 시스템 한글 폰트를 불러온 위젯 테스트이며 일부 기존 필터 라벨의 대체 폰트는 캡처 환경 제약.
- 인메모리·임시 테스트 DB만 사용; 사용자 거래 데이터 변경 없음.

## 계산 범위

카드사별 수수료, 선결제의 개별 거래 지정, 실제 명세서 조회는 포함하지 않는다. 회차별 원금은 일정 안내이고, 총 청구액은 입력 거래에 따른 추정치다. 총 구매금액 기준으로 예산과 지출을 기록한다.
