# 반복 거래 목록 순서 편집

Status: ready-for-human

## 동작

- PC·모바일 반복 거래 페이지의 `순서 편집` 버튼에서 목록을 편집한다.
- 드래그 손잡이와 위·아래 이동 버튼을 제공하고 `순서 저장` 또는 `취소`로 마무리한다.
- 저장된 사용자 순서가 활성/비활성 상태보다 우선한다. 활성 상태 변경으로 항목 위치가 움직이지 않는다.
- 신규 반복 거래는 현재 순서의 끝에 추가하며 기존 거래 편집은 위치를 보존한다.
- 원본 목록의 항목 수가 바뀐 오래된 편집은 오류를 표시하고 저장하지 않는다. 도중 오류도 전체 원복한다.
- 금액, 반복 주기, 이미 생성한 거래와 생성 기준일은 순서 변경으로 수정하지 않는다.

## 저장과 호환

- 스키마 24: recurring_transactions.sort_order 정수 필드를 기본값 0으로 추가한다.
- 기존 데이터는 같은 0 안에서 활성 우선·ID 순을 유지한다. 순서를 저장하면 0부터 연속 값으로 정한다.
- 순서 갱신은 DB 트랜잭션으로 처리하고 수정 일시와 동기화 상태도 갱신한다.
- 백업에 순서를 포함한다. 이전 백업의 필드 누락은 0으로 처리한다.
- 증분 동기화에 sort_order를 포함하고 이전 클라이언트가 필드를 생략하면 기존 로컬 순서를 보존한다.
- PC·모바일은 각 전용 화면에 버튼을 추가하고 공통 편집 다이얼로그만 공유한다.

## 검증

- PC·모바일 위/아래 이동, 드래그, 저장·취소·재편집을 확인한다.
- 저장 순서, 활성 전환, 신규 추가, 백업 왕복, 이전 백업, 이전 동기화 payload, v23 마이그레이션을 확인한다.
- 잘못된 ID/중복/누락 및 중간 쓰기 실패 시 부분 저장이 없는지 확인한다.
