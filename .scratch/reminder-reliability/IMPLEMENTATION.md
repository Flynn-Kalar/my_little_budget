# Android 리마인더 적용 기록

작성일: 2026-10-15. Windows 알림 어댑터는 이번 범위에서 제외.

## 사용 흐름

모바일 메모를 만들거나 편집하여 마감일을 독립적으로 지정한다. 기존 반복 선택에 간격·종료일·시간대를 추가하고 다음 3회 날짜를 확인한다. 알림을 켜면 일반 알림/최대 60초간 울리는 알람을 선택할 수 있다. 기존에 저장된 알람은 알람 모드를 유지한다.

알림과 알람 화면의 완료는 해당 회차만 완료한다. 다시 알림은 지정된 스누즈 값(미설정 시 10분)을 사용하고 반복 기준일은 바꾸지 않는다. 알람 끄기는 완료와 별개다. 메모 카드에서 현재 회차 완료/취소, 이전 회차에서 과거 완료/취소/건너뛰기를 할 수 있다. 권한이 없어도 메모는 저장되며 예약 상태에 권한 필요/대기/실패를 표시한다.

## 저장과 호환성

- DB 버전 20. 기존 Notes와 체크리스트는 유지하고 reminder_series, reminder_occurrences, reminder_jobs를 추가했다. 추가 테이블은 Dart가 마이그레이션하며 Android는 같은 DB를 읽고 짧은 트랜잭션으로 액션을 기록한다.
- 예약 대기/취소 상태가 OS 작업 의도 기록 역할을 한다. DB ID로 안정적 notification ID를 할당하고 generation으로 이전 payload와 중복 액션을 거부한다.
- 기존 SharedPreferences JSON은 OS에 등록된 ID를 취소하는 호환 목록으로만 사용한다. 실제 예약/미루기의 원본은 SQLite다.
- 체크리스트를 리셋하기 전에 회차 스냅샷을 보존한다. 현재 회차 완료가 다음 회차 알림을 막지 않는다. 과거 기록은 추측해서 채우지 않는다.
- 백업 JSON에 시리즈 설정·회차 이력을 선택 필드로 추가해 구 백업과 호환한다. 기기별 OS 예약 ID와 미루기 작업은 백업에 복원하지 않고 새 기기에서 재계산한다.
- 반복은 저장된 IANA 시간대의 달력 기준. 월말 보정 후 원래 날짜 복귀, 윤년 복귀, DST 결손은 다음 유효 분/중복은 첫 시각 정책을 적용했다.
- 기본 미래 30회차와 선행 알림의 날짜 차이를 감안한 추가 회차를 계산한다. Android에는 가까운 작업 최대 400개를 등록하고 나머지 의도를 보존한다. 400은 앱의 예약 예산이다.
- 재생 시각에 최신 회차/예약을 확인한다. 지연 5분 초과는 놓친 알림으로 처리하고 요약만 표시한다. 완료 취소로 지난 알림을 되살리지 않는다.

## Android 실행

- 기존 AlarmManager, MediaPlayer, Vibrator, 잠금 화면 UI를 확장했다. 동시에 들어온 알람은 재생 세션 하나에 모으며 남은 작업은 알림에서 처리할 수 있다.
- 부팅·앱 업데이트·시간/시간대 변경·정확한 알람 권한 변경 이벤트를 연결했다. 수신 후 화면 없는 Flutter 엔진이 DB 예약 범위를 보충한다. 엔진은 시간 제한을 가지며 실패하면 기존 예약을 유지하고 상태를 남긴다.
- 네트워크 동기화보다 로컬 예약을 먼저 독립적으로 시작한다. 예약 재조정 중 변경이 들어오면 다시 실행한다.
- 전체 화면 권한은 저장 전제 조건에서 제거했다. 전체 화면이 허용되지 않으면 알림으로 접근한다. 정확한 알람/알림 권한이 막히면 예약 성공으로 표시하지 않는다.
- 사용자 음원 접근/디코드 오류의 시스템 음원 대안, 구간 반복, 오디오 포커스 상실 시 정지, wake lock 정리를 추가했다.

## 검증 자료

최종 기능 검증: Flutter 테스트 376개 통과, flutter analyze 이상 없음. Android 15 실제 기기 테스트 8개 통과(화면 없는 실제 Drift DB 예약 계약, 예약 수신·재생 시작·정지 포함).

- Flutter 전체 테스트: `all-tests.log`.
- 코드 분석: `analyze.log`.
- 반복/예약/백업/마감일 경계 테스트: `store-tests.log`.
- Android 실제 기기 테스트: `android-device-tests.log`. 연결 기기 SM-G991N, Android 15/API 35.
- Android 테스트는 별도 `.remindertest` 패키지와 테스트 DB를 사용한다. 기존 설치된 가계부 DB를 테스트 데이터로 사용하지 않는다.
- 네이티브 테스트는 구세대 수신, 중복 완료/미루기, 삭제·해제, 동시각 별개 작업, 화면 없는 Dart/Android DB 계약, AlarmManager 수신→MediaPlayer.start()→정지를 확인한다. MediaPlayer 시작 기록은 사람이 실제 소리를 들었다는 증거와 구분한다.

## 남은 실기기 확인과 제약

- 장시간 Doze/재부팅/강제 중지 후 복귀/기기별 배터리 절약/DND/볼륨 0/전체 화면 권한 조합/실제 통화 중 동작은 자동 테스트 완료로 표시하지 않는다.
- 전원 꺼짐과 사용자의 강제 중지 동안 알람을 보장하지 않는다. 정확한 알람 권한·전체 화면·foreground service는 OS 및 Google Play 제약을 따른다.
- 현재 미래 회차가 누적 생성되지만 과거 이력 자동 정리 정책은 도입하지 않았다. 목록의 이전 회차 화면은 최근 60개를 표시한다.
- 마감일은 날짜 정보이고 알림 예약을 자동으로 활성화하지 않는다. 기존 금액 목표의 마감일과 별개다.
- CalendarEvents 알림의 통합, Windows/iOS/Web 종료 후 알림, 기기 간 중복 조정은 후속 범위다.
- 이번 작업에서는 기존 사용자의 가계부 앱을 덮어쓰지 않았다. 테스트용 설치와 빌드 산출물을 구분한다.
- 배포 APK와 debug APK 빌드 성공. 기존 키 저장소와 서명 키를 유지하고 로컬 android/key.properties의 비밀번호 설정을 바로잡았다. key.properties는 Git 제외 대상이다. 배포 산출물: build/app/outputs/flutter-apk/app-release.apk (77.7MB).
