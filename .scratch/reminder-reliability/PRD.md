# 가계부 리마인더 신뢰성 개선 계획

Status: needs-triage
작성일: 2026-10-15
범위: 설계 제안. 이번 작업에서 앱 코드·DB·예약은 변경하지 않는다.

## 1. 목표와 범위

기존 메모·체크리스트 리마인더와 Android 알람을 확장한다. 마감일, 반복 회차, 알림 예약, 알람 재생 상태를 분리하여 완료·수정·다시 알림 이후에도 올바른 회차만 울리게 한다.

- 우선 구현: 기존 기능 이전과 Android 실동작 검증. Windows는 동일 도메인 모델에 별도 OS 어댑터를 붙이는 후속 단계까지 계획한다.
- 일반 메모, 할 일, 캘린더 일정을 구분한다. 할 일 완료가 거래 생성·정기 거래 실행·계좌 잔액 변경을 유발하지 않는다.
- 기존 메모 내용·서식·체크리스트·음원·반복 설정을 보존한다. 할 일을 위해 별도 메모 앱을 새로 만들지 않는다.
- 기존 Supabase 동기화 범위를 임의 확장하지 않는다. 새 회차·예약은 우선 기기 로컬이며 기기 간 중복 조정은 제외한다.
- iOS/Web는 지원 상태 표시와 데이터 호환성을 유지한다. 이번 1차 구현에서 종료 후 알람을 보장하지 않는다.
- 첨부 가이드의 Microsoft To Do 정적 분석 결과는 참고 근거다. 회차 모델과 아래 정책은 이 가계부를 위한 신규 제품 결정이다.

## 2. 현재 코드에서 확인한 사실

| 영역 | 현재 구현 | 적용 방향 |
|---|---|---|
| 저장 | Drift SQLite, schemaVersion 19. Notes에 반복·알림·음원·nextResetAt, 별도 체크리스트 테이블 | 기존 Notes 유지, 회차·예약 보조 테이블 추가 |
| 반복 계산 | note_schedule.dart에 매일·주간 복수 요일·평일·주말·월간·연간·N일 간격. 월말 보정 존재 | 검증된 계산 재사용, 시간대·간격·회차 식별 확장 |
| 완료 | 체크리스트 전체 체크 시 예약 제외. Notes.completed는 레거시 호환용 | 회차별 완료로 전환. 미래 회차까지 일괄 제외하지 않음 |
| 반복 리셋 | reconcileRecurringNotes가 현재 체크리스트를 미완료로 되돌림 | 과거 회차 스냅샷 보존 후 다음 회차 노출 |
| 예약 | Android 전용. 미래 90일 후보를 정렬하고 최대 400개, ID=740000+목록 순번 | 안정적 ID·예약 상태·변경분 재조정 도입. 400은 현재 앱 값이며 OS 보장 한도 아님 |
| 네이티브 저장 | SharedPreferences JSON 전체 교체, 부팅·앱 업데이트 시 저장 예약 재등록 | SQLite 의도 상태를 기준으로 복구. JSON은 마이그레이션 후 권위 저장소에서 제외 |
| 알람 도착 | Receiver가 payload를 Service에 전달. DB 회차·generation 확인 없음 | 최신 상태 확인 뒤 재생 |
| 재생 | Kotlin MediaPlayer/Vibrator, 사용자 음원 구간 반복, 60초 타임아웃, 전체 화면·알림 대안 | 재사용하되 회차 식별·경쟁·오류 복구 추가 |
| 다시 알림 | 기존 payload의 triggerAt 수정 후 같은 ID 재예약 | DB에 영속 저장하여 rebuild에도 보존 |
| 플랫폼 | NoteNotificationService.isSupported는 Android만 true | Windows 예약·소리 지원은 별도 검증 필요 |
| 캘린더 | CalendarEvents에도 알림 필드가 있지만 현재 NoteNotificationService는 Notes만 읽음 | 우선 메모/할 일 완성, 캘린더 연결은 동일 Job 엔진의 후속 단계 |

주요 파일: lib/features/notes/{note_schedule,note_alarm,note_notification_service}.dart, lib/data/daos/notes_dao.dart, lib/data/tables/notes.dart, lib/app.dart, android/app/src/main/kotlin/com/my_little_budget/NoteAlarm{Bridge,Activity,PlaybackPolicy}.kt.

## 3. 데이터 구조

### 기존 Notes: 시리즈/메모의 본체

제목·내용·중요 표시(pinned와 의미 구분)·음원·체크리스트 템플릿은 재사용한다. 중요 표시는 상단 고정과 다르므로 필요하면 별도 필드를 추가한다.

추가 논리 필드: kind(note/task), dueDate(날짜, nullable), seriesTimeZone(IANA), recurrenceRule, revision, deletedAt. 일회성 알림은 UTC 시각을 저장하고 마감일과 독립시킨다. goalDueDate는 목표 금액용이므로 할 일 마감일로 재사용하지 않는다.

반복 규칙: unit(day/week/month/year), interval(1~365), anchorDate, weekdays(ISO 1~7), untilDate(포함), ruleSegmentId. 기존 평일·주말은 요일 규칙으로, N일 반복은 day+interval로 변환한다. 기존 resetTime은 회차 시작 시각으로 호환하되 마감 시각과 혼동하지 않도록 UI 문구를 분리한다.

### NoteOccurrences: 각 회차의 상태

- id, noteId, ruleSegmentId, occurrenceKey, scheduledDate, status(pending/completed/skipped), completedAtUtc, revision.
- UNIQUE(noteId, occurrenceKey). 키는 규칙 구간과 논리 예정 날짜로 정하며 UTC 알림 시각·배열 인덱스를 사용하지 않는다.
- 회차별 체크리스트 상태/템플릿 스냅샷을 별도 저장한다. 새 회차는 미완료로 시작한다.
- 규칙 수정은 새 규칙 구간을 만들되 완료/건너뛴 회차를 보존한다. 단순 알림 시각 변경은 회차 키를 바꾸지 않는다.
- 일회성 작업도 회차 하나로 표현한다. 체크리스트 없는 할 일도 명시적으로 완료 가능하다.

### ReminderJobs: 기기별 예약과 실행 기록

- id, occurrenceId, reminderRuleKey(당일/사전 알림 등), fireAtUtc, generation, platformRequestId, snoozedUntilUtc, schedulingStatus, deliveryStatus, playbackStatus, lastError, retryAtUtc.
- 예약 상태: pending/scheduled/blocked/cancelled/failed. 전달 상태: unknown/posted/dismissed/missed. 재생 상태: idle/ringing/stopped/timedOut/failed. OS 표시 요청과 사용자가 실제로 봄/들음을 구분한다.
- platformRequestId는 DB 할당·유일성 제약으로 안정적으로 유지한다. 미루기는 같은 회차에 활성 예약 하나만 유지한다.
- UNIQUE(occurrenceId, reminderRuleKey) 등으로 정규 알림 중복을 막는다. 서로 다른 할 일이 같은 시각인 것은 중복으로 삭제하지 않는다.

### ReminderOutbox / ActionReceipts

예약 등록·취소 의도를 도메인 변경과 같은 DB 트랜잭션에 기록한다. OS 호출 후 결과와 재시도를 기록한다. 액션 ID 유일성 제약으로 완료/미루기 중복 요청을 무해하게 처리한다.

Android의 앱 종료 중 액션도 같은 상태를 읽고 변경해야 한다. 단계 0에서 Drift 생성 스키마를 읽는 최소 Kotlin SQLite 저장소를 시제품으로 검증한다. 스키마 마이그레이션은 Dart만 수행하며 Kotlin에서 임의 생성/업그레이드하지 않는다. DB 잠금·WAL·짧은 트랜잭션·앱 복귀 후 provider 갱신을 검증한다. 네이티브 저장소와 Dart의 계약 테스트를 유지한다. 백그라운드 DB 접근을 검증하기 전 단순 callback 연결을 종료 중 완료 지원으로 보고하지 않는다.

## 4. 예약·취소·완료·다시 알림

| 동작 | 처리 기준 |
|---|---|
| 생성 | 제목·날짜·간격 검증 → Notes/회차/Jobs/Outbox 트랜잭션 → OS 예약 → 성공/차단 상태 표시 |
| 마감일만 지정 | 저장 가능, 알림 자동 활성화 안 함. 마감일 없이 일회성 알림도 가능 |
| 수정 | 기본 현재 및 이후. 완료/건너뛴 과거 보존. generation 증가, 기존 예약 취소 후 새 예약. 새 시리즈와 겹치는 날짜 중복 검사 |
| 알림 끄기 | 해당 범위 Jobs 취소·현재 재생 중지. 할 일은 유지 |
| 회차 완료 | 해당 회차·하위 항목 완료, 그 회차의 사전/정규/미루기 예약과 표시 알림·재생 취소. 다른 회차는 유지 |
| 완료 취소 | 해당 회차만 복구. 과거 알림 자동 재전송 안 함. 미래 알림만 재조정 |
| 삭제 | 회차 삭제는 skipped 보존. 시리즈 삭제는 미래 회차·예약과 현재 재생 취소. 메모 삭제 정책과 연결 |
| 다시 알림 | 기본 10분, 선택 1시간/직접 지정. 현재 소리·진동 즉시 중지 후 같은 회차의 미루기 예약 하나를 영속 저장. 마감일/반복 기준 불변 |
| 연속 미루기 | 이전 미루기를 대체. 미루기 시각까지 같은 회차의 다른 정규 알림이 중복 울리지 않게 억제. 그 이후의 명시적 사전 알림과 다음 회차는 유지 |
| 알람 끄기/해제 | 소리·진동/현재 표시만 해제. 완료 처리나 자동 미루기 없음 |
| 알림 열기 | noteId+occurrenceId로 정확한 회차에 진입. 삭제된 회차는 안전하게 안내 |

도착 시 note/occurrence/job/generation/상태를 다시 확인하고 구버전·완료·삭제·처리된 요청을 억제한다. 모든 버튼 payload에 jobId·occurrenceId·generation·actionId를 넣고 오래된 알림의 액션도 검증한다. 정확히 한 번 전달을 약속하지 않으며 고정 notification ID와 저장 제약으로 중복을 줄인다.

예약 재조정은 단일 실행+dirty 재실행으로 직렬화한다. 현재 _notesSyncing 중 변경을 단순 return으로 버리는 구조를 피한다. 시작·복귀·변경·도착·권한 복구·부팅·시간 변경 때 실행한다. 로컬 예약 초기화가 네트워크 동기화 성공이나 응답 시간에 종속되지 않게 한다.

## 5. 날짜·시간대·누락·한도 정책

- 예정일 기준 반복. 늦게 완료해도 다음 날짜를 완료일 기준으로 밀지 않는다. 과거 미완료는 보존하고 기본 목록은 시리즈별 다음 미완료를 표시한다.
- 1월 31일 매월 → 2월 말일 → 3월 31일. 직전 보정 날짜가 아닌 anchorDate를 기준으로 계산한다.
- 2월 29일 매년 → 평년 2월 28일 → 윤년 2월 29일 복귀.
- N주 복수 요일은 월요일 시작 기준 주와 간격을 저장한다. N개월/N년과 종료일도 동일 규칙 계산기를 사용한다.
- 날짜는 YYYY-MM-DD, 기록/발화 시각은 UTC, 반복은 저장된 IANA 시간대의 현지 달력으로 계산한다. 생성 시 기기 시간대를 저장하고 여행 시 자동 변경하지 않는다. 사용자가 시간대를 바꾸면 미래 회차만 재조정한다.
- DST 결손 시각은 다음 유효 시각, 중복 시각은 첫 번째. 앞당긴 알림은 현지 날짜 차이+시각으로 계산한다. 분 단위 선행 알림은 실제 경과 시간 차이로 계산한다.
- 새 과거 알림은 입력 오류. 회차 마감일 자체가 과거인 것은 허용한다. 복구 시 지난 알림은 missed로 보존하고 놓친 알림 요약 하나만 제공한다.
- 수신 지연 유예안: 예정 후 5분 이내면 한 번 알림, 그 이상이면 missed. 강제 중지·전원 꺼짐·OS 절전에서 정확한 울림을 보장하지 않는다. 유예값은 설정 상수가 아니라 명시적 제품 정책으로 테스트한다.
- 시리즈당 미래 30회차를 계산하되 정규/사전 알림 수와 구분한다. 전체 Jobs를 시각순으로 선택하고 플랫폼별 검증된 예약 예산을 적용한다. 90일 일괄 잘라내기로 연간 알림을 누락하지 않는다.
- 발생 처리 때 다음 예약을 보충한다. 장기간 미실행 시 보충은 Android 네이티브 실행 가능 범위에서 검증한다. 무한 반복·증가하지 않는 계산·예약 개수 폭증은 중단하고 오류 기록한다.

## 6. 알람 울림

Android는 현재 재생 서비스를 재사용한다. 일반 알림과 알람을 별도 선택하게 하고 기본은 일반 알림으로 제안한다. 기존에 사용자가 설정한 알람은 자동으로 일반 알림으로 바꾸지 않는다.

- 알람 모드: 시스템 알람음/사용자 음원, 구간 재생, 진동 설정. 최대 60초 울림 후 정지하며 미완료 유지, 무한 자동 반복 금지. 반복 음원과 다시 알림은 별개다.
- 소리/진동/오디오 포커스/알람 볼륨/방해 금지/채널 설정을 존중한다. 소리 차단을 우회해 미디어 채널로 재생하지 않는다. 무음·채널 차단·볼륨 0·기기 진동 미지원 상태를 구분한다.
- 음원 파일은 앱 보관 경로 또는 지속 접근 권한을 사용한다. URI 소실·디코드 오류·유효하지 않은 구간은 시스템 알람음으로 대체 시도하고 오류 상태를 남긴다. 두 소리를 동시에 재생하지 않는다.
- 같은 시각 여러 회차: 각각 기록/액션은 유지하되 재생 세션은 하나로 병합하여 소리가 겹치지 않게 한다. 화면에 함께 울린 할 일을 표시하고 개별 완료/미루기 및 모두 소리 끄기를 제공한다. 새 도착이 기존 세션을 조용히 덮어쓰지 않게 한다.
- 화면은 완료/다시 알림/알람 끄기를 구분한다. 현재 스와이프 끄기 동작을 완료로 오인하지 않게 유지한다. 타임아웃·삭제·완료·통화/오디오 인터럽트·Service 종료 시 player/vibrator/wake lock/notification 정리.
- 알림 권한·정확한 알람 권한·전체 화면 권한을 분리 표시한다. 전체 화면 불가 시 알림에서 동일 액션에 접근 가능해야 한다. 정확한 알람 불가 시 예정 시각 보장을 표시하지 않으며 지연 가능 알림을 사용자가 선택하거나 blocked로 둔다.
- 가계부는 전용 알람 앱이 아니므로 전체 화면 자동 허용을 전제하지 않는다. Google Play의 전체 화면·foreground service 적합성 검토를 출시 전 관문으로 둔다. 일반 알림 동작은 전체 화면 권한에 의존하지 않는다.
- 알람 테스트 버튼: 단순 음원 미리듣기와 실제 1분 뒤 예약 시험을 분리한다. 시험 중 앱 종료/잠금 후 도착 여부까지 확인한다. 마이크로 실제 소리를 검증하지 않았다면 API 성공만으로 울림 확인이라 쓰지 않는다.

Windows: 별도 어댑터에서 앱 식별/설치 등록, OS 예약 알림과 완료·미루기 activation을 우선 시제품으로 검증한다. 설치 EXE와 개발 실행을 각각 시험한다. OS 예약 토스트가 가능해도 Android식 반복 음원·종료 중 서비스·절전 해제를 지원한다고 단정하지 않는다. 종료 중 울리는 알람이 필수이면 별도 상주 프로세스/시작 옵션의 필요성과 수명주기를 먼저 결정한다. 1차 Windows 목표는 OS 예약 알림과 지원 상태 표시이며 Android와 같은 강제 울림은 별도 범위다.

## 7. 이전과 UI

- 다음 schemaVersion으로 단계적 마이그레이션. 먼저 백업/검증, 구버전 DB와 설정을 fixture로 테스트한다. 실제 사용자 DB는 계획 단계에서 변경하지 않는다.
- 기존 알림/반복/음원 설정을 보존하고 현재 회차만 생성한다. 이전 완료 이력은 추측해 만들어내지 않는다. 사용자에게 현재 회차를 이전한 기준을 명시한다.
- 기존 체크리스트가 모두 체크된 현재 회차는 완료로 이전하되 미래 회차는 미완료로 생성한다. 체크리스트 없는 메모는 레거시 completed만으로 무조건 할 일 완료를 추론하지 않는다.
- 네이티브 JSON 예약은 새 DB 기록 확정 후 구 ID를 취소하고 새 ID 등록. 이전 중 프로세스 종료에도 재실행 가능한 migration checkpoint 사용. 구세대 브로드캐스트는 전환 후 억제한다.
- 모바일 화면은 lib/ui/mobile, PC/태블릿은 lib/ui/desktop에서 각각 작성한다. shell과 lib/shell/layout_policy.dart의 플랫폼/폭 정책을 유지한다.
- 오늘/예정/완료, 과거 미완료 펼치기, 반복 다음 3회 미리보기, 예약 성공/권한 필요/예약 대기/실패를 표시한다. 권한 없는 플랫폼에서 가짜 예약 성공을 표시하지 않는다.
