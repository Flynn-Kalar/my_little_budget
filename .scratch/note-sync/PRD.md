# 메모 동기화와 기기별 알람

Status: local implementation complete; server schema application pending

- 기존 메모는 증분 동기화 대상에서 누락되어 있다. notes를 UUID·변경 추적·삭제 기록·서버 소유자 정책을 포함한 정식 동기화 대상으로 추가한다.
- 제목·본문·리치 텍스트·체크리스트 및 완료 상태·고정·목표·캘린더 표시·일정·반복 주기/종료일을 공유한다.
- 알림 활성·알림 시각·사전 알림·소리 및 파일 경로·진동·다시 알림·전체 화면 모드와 예약/발송 이력은 공유하지 않는다. 받은 새 메모는 알람 기본 꺼짐, 기존 메모의 기기별 알람 값은 유지한다.
- DB v24→v25에서 기존 메모·체크리스트·알람을 유지하고 UUID를 부여하며 전송 대기열에 등록한다. 기존 백업도 읽을 수 있어야 한다.
- 체크리스트와 반복 상세 설정은 메모 payload에 포함하고 로컬 숫자 ID는 전송하지 않는다. 편집 초안과 과거 회차 알림 이력은 로컬에 남긴다.
- 서버에는 mlb_notes 테이블 추가가 필요하다. 기존 전체 설치 SQL과 앱 내 설치 안내를 11개 테이블로 갱신한다.
- 최초 구현 요청에서는 로컬 반영만 수행했다. 후속 배포 요청에 따라 rc.9(58) 배포에 포함한다.

## 검증

두 로컬 기기와 가상 서버로 내용/체크 상태/수정/삭제 왕복, 알람 미전송 및 기기별 설정 유지, 이전 백업과 DB 마이그레이션, 오류 발생 시 원자성을 검증한다.

- 새 동기화 테스트 6개 통과. 내용·서식·목표·체크리스트·삭제 왕복, 기기별 모든 알람 값 보존, 잘못된 payload 롤백, v24 마이그레이션과 이전 백업, 전송 중 알람/리셋 갱신에 의한 generation 변경 방지를 확인했다.
- 전체 테스트 531개 통과. 정적 분석 문제 없음.
- Supabase 대시보드 접속 결과 로그인 화면이므로 실제 서버 SQL은 적용하지 못했다. 관리 로그인 후 최신 전체 SQL 실행과 11 / 11 확인이 필요하다.
- 최초 검증 당시 앱 배포·GitHub 푸시·AAB 생성은 수행하지 않았다. 후속 rc.9 배포 결과는 `.scratch/release-rc9/RELEASE_NOTES.md`와 로컬 `installer/output/release-result.json`에서 확인한다.
