# 일상 편의성 개편 구현 결과

Status: ready-for-human

## 사용 위치
- PC 내역의 메모 자동완성: 같은 유형의 최근 거래 최대 300건에서 중복 메모를 제거해 제안. 계좌·카테고리·태그 설명을 표시하고 선택 시 함께 적용. 금액·날짜·시간은 유지.
- 모바일 신규 거래: 메모 검색어에 맞는 최근 입력 최대 3개를 표시. 기존 거래 편집에는 표시하지 않음.
- 내역의 체크리스트 버튼: 현재 조회/필터 결과에서 여러 거래 선택 후 카테고리·태그 일괄 변경. PC는 접힌 검색·필터 옆에 배치.
- 예산 화면: 그룹별 남은 기간 하루 사용 가능액 표시. 오늘 포함, 나눗셈 내림, 초과 예산 별도 안내, 지난달 제외, 미래 월은 전체 일수 기준.
- 설정 > 데이터 백업/복원 > 로컬: CSV 내보내기/가져오기와 자동 백업 관리.

## 데이터 처리
- 일괄 수정은 모든 대상과 카테고리 유형을 검사하고 단일 트랜잭션으로 저장. 태그 변경은 기존 태그 전체 교체이며 빈 입력은 모두 제거.
- CSV는 UTF-8 BOM, RFC 4180 따옴표·줄바꿈, 엑셀 수식으로 해석될 수 있는 텍스트 보호, 한글/영문 거래 유형을 지원.
- 가져오기는 열 연결 후 전체 검증. 날짜·시간·유형·금액·계좌·분류·메모·태그가 같은 기존/파일 내 중복은 제외. 오류 행이 있으면 전체 가져오기 금지. 저장 직전 중복과 참조를 다시 확인하고 원자적으로 저장.
- CSV는 10MB·10,000건 한도. 계좌/카테고리는 기존 활성 이름으로 연결하며 새 계좌/카테고리 생성은 하지 않음. 투자 이벤트는 CSV 대상이 아니며 일반 거래와 잔액 조정만 포함.
- 자동 백업은 설치형 앱에서 기본 활성화, 시작 시·변경 후 10초·사용 중 매시간 점검하여 하루 한 번 생성. 앱 내부 `local_backups`에 최근 7개 보관. 수동 복구 지점은 추가 생성 가능.
- 백업 내보내기는 DB 읽기 트랜잭션으로 일관성을 보장. 임시 파일 작성과 flush 후 rename하고 성공 후에만 오래된 복구 지점 삭제.
- 로컬 파일/원격 JSON/복구 지점 복원 모두 날짜·건수 확인 후 진행. 설치형 앱에서는 직전 안전 백업이 성공해야 복원하며, 이미 진행 중인 자동 백업도 기다린 뒤 새로운 안전 백업 생성.
- 계좌·카테고리·태그 메타데이터 변경 시 추천 갱신. 거래 변경 후 계좌별 내역과 통계 상세도 갱신.
- 웹에는 자동 로컬 백업을 제공하지 않음. JSON 내보내기와 기존 백업 기능 사용.

## 검증
- `flutter analyze --no-pub`: 문제 없음.
- 전체 `flutter test --no-pub`: 425개 통과.
- 이후 추가한 추천 캐시 갱신 및 백업 실패 보존 테스트 2개 포함 데이터 테스트 파일: 9개 통과. 총 427개의 서로 다른 테스트 검증.
- 신규 UI 테스트 4개: PC 추천 적용 시 금액·날짜·시간 보존, 모바일 추천 및 저장, 모바일 일괄 태그 수정, 모바일 CSV 중복 미리보기 및 가져오기.
- 기존 좁은 PC 500/600/800px 및 Android/iOS 레이아웃, 백업·Supabase 설정, 거래 자동완성 회귀 검증 통과.
- 삭제 실행 취소 및 제안 후반의 화면 재배치/월말 결산은 제외.
