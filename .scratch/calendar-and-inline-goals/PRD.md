# 캘린더 일정 알림·회차 편집과 메모 본문 금액 목표

Status: ready-for-human

## 사용자 요청

삼성 캘린더 분석보고서와 현재 가계부 비교에서 제안한 개선을 적용한다. 우선 캘린더 알림 연결, 이번 회차만 수정·건너뛰기, 종일 날짜·시간대 처리를 구현하고 간격·종료일·미리보기 및 저장/동기화/예약 상태를 보완한다. 금액 목표는 메모 전체의 유형만 선택하는 방식 외에 본문 중간에 체크리스트처럼 삽입할 수 있어야 한다.

## 구현 정책

- 기존 메모·체크리스트·상단 금액 목표를 유지한다. 본문 목표는 여러 개 삽입할 수 있으며 이름·금액·날짜·추가 금액을 각각 수정한다. Quill의 기존 richContent에 식별자와 블록 데이터를 보존하고 읽기·검색용 평문도 생성한다. 저장·초안·복구·실행 취소·백업 경로를 재사용한다.
- DB v22에 calendar_events.schedule_data JSON을 추가한다. 반복 간격, 종료일, IANA 시간대, 종일 날짜, 원래 회차 날짜별 예외를 저장한다. 기존 이벤트는 유지하고 종일 날짜는 최초 업그레이드 때 현지 날짜로 고정한다. 예전 UTC 시각만으로 원래 생성 기기의 시간대를 역추정하지 않는다.
- 일정 표시와 알림은 같은 회차 계산기를 사용한다. 월말·윤년의 기준일을 유지하고 회차 이동 후에도 원래 날짜로 식별한다. 이번 회차 수정/건너뛰기와 전체 일정 수정을 구분하며 예외 목록에서 복원할 수 있다.
- 일정 알림은 calendar_occurrences/calendar_jobs에 저장하고 기존 Android 예약·수신·재부팅 복구 경로에 연결한다. 기존 메모의 테이블·양수 알림 ID는 유지한다. 일정의 작업 토큰과 알림 ID는 음수로 구분한다. SQLite view의 계산된 ID는 네이티브 조회 시 명시적으로 정수로 비교한다.
- 일반 일정 알림에 확인/다시 알림을 제공한다. 확인은 해당 회차의 알림 확인일 뿐 거래 생성이나 잔액 변경이 아니다. 종일 일정 알림의 기본 시각은 저장 시간대의 09:00이며 UI에 안내한다.
- 권한 거부·예약 실패를 성공으로 표시하지 않는다. 로컬 저장과 서버 동기화 상태를 구분한다. 캘린더 설정/예외는 기존 Supabase JSON payload에 포함하므로 서버 테이블 변경이 필요 없다. 이전 payload와 백업은 기본값으로 읽는다.
- 회차 확인 상태는 로컬과 백업에 보존한다. OS 예약/미루기 작업은 기기별 데이터이며 다른 기기에 복원하지 않는다. 기기 간 알림 중복 조정, 외부 캘린더 연동, 음력 반복은 이번 범위에 포함하지 않는다.
- PC와 모바일 화면을 각각 수정하며 기존 배경색·테마·shell 분기는 유지한다.

## 검증

기존 전체 테스트, 추가 회차/동기화/마이그레이션/목표 블록 테스트, PC·모바일 사용자 흐름 테스트, Android 별도 테스트 패키지의 네이티브 계약 테스트 및 플랫폼 빌드로 확인한다. 사용자가 설치한 실제 가계부 데이터는 테스트하지 않는다.
